## Live Quantura MCP

Server URL: **`https://quantura.studio/mcp`**

Transport: stateless Streamable HTTP with JSON responses. Protocol discovery and the tool catalog are public. Every tool call requires Pro (including an active 14-day trial), enterprise or verified administrator access and checks current account and resource permissions. Active 14-day Pro trials include API and MCP access.

| Tool | Action |
| --- | --- |
| `quantura_search_markets` | Search stocks, FX, prediction markets, economic databases and SageMaker forecasts |
| `quantura_forecast_models` | Inspect models, frequencies and minimum history |
| `quantura_get_forecast` | Read an authorized forecast and its quantiles |
| `quantura_create_forecast` | Create a forecast job with a required idempotency key |
| `quantura_download_history` | Retrieve JSON provider history; follow `next_cursor` for paged requests |
| `quantura_ask_scout` | Ask a grounded question using authorized forecast or CSV context |
| `quantura_my_access` | Inspect current account API access |

Forecast creation uses compute and saves a request; Scout saves a conversation. These actions are marked as mutations for clients to review. No tool places trades.

## Connect ChatGPT

1. In ChatGPT, open **Plugins → + → Add custom MCP server**. If custom MCP is unavailable, check developer mode and workspace permissions.
2. Name it **Quantura** and enter `https://quantura.studio/mcp`.
3. Choose **OAuth**. Select client metadata (CIMD) or dynamic registration when offered; no manually copied client secret is needed.
4. Create and install the plugin, then sign in to your Quantura account through Clerk and approve access.
5. Start with “Search for AAPL in Quantura and show the available forecast models.”

The CLI's public OAuth client is for its loopback callback only; do not paste its client ID into ChatGPT. ChatGPT registers its own callback through CIMD or dynamic registration. Interface and workspace policy can change; see [OpenAI's current connection guide](https://developers.openai.com/api/docs/guides/custom-mcp-server).

The read-only `quantura_verify_forecast` tool verifies saved forecast content against a vBase timestamp receipt. [Receipt guide](/docs/forecast-receipts).

## OAuth discovery

Protected-resource metadata:

```text
https://quantura.studio/.well-known/oauth-protected-resource/mcp
```

The REST API and MCP share the protected resource `https://quantura.studio`. The authorization server is `https://clerk.quantura.studio`; discovery advertises PKCE S256, client metadata and dynamic registration. Clients pass the discovered resource in authorization and token requests. Quantura rejects revoked, expired or wrong-audience tokens and requires `openid profile email`. CLI clients also request `offline_access` for refresh.

Unauthenticated tool calls return HTTP 401 with a `WWW-Authenticate` metadata challenge. Valid unpaid accounts return 403 instead of prompting repeated sign-in. The transport also accepts a paid user's personal API key when a client supports securely stored bearer credentials.

## Verify without credentials

```bash
curl https://quantura.studio/.well-known/oauth-protected-resource/mcp
curl -X POST https://quantura.studio/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-11-25","capabilities":{},"clientInfo":{"name":"quantura-check","version":"1.0.0"}}}'
```

OAuth-capable clients can use:

```json
{"mcpServers":{"quantura":{"type":"http","url":"https://quantura.studio/mcp"}}}
```

Configuration syntax varies by client. Store credentials in the client's secret facility, never in a URL or checked-in configuration.

`https://quantura.mintlifysite.com/mcp` is the separate Mintlify documentation server. It provides documentation search and whichever read-only OpenAPI tools the host enables. Use `/mcp` on `quantura.studio` for the eight live tools above.
