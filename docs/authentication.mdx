# Authentication and API keys

## OAuth sign-in

The [Quantura CLI and SDKs](/docs/sdk-cli) and [live MCP server](/docs/mcp) support Clerk authorization-code OAuth with PKCE S256. Run `quantura login` or connect an OAuth MCP client to `https://quantura.studio/mcp`. Tokens are bound to the shared resource `https://quantura.studio`; clients pass this resource in authorization and token requests. Identity scopes are `openid profile email`, with optional `offline_access` for refresh. Current pay-as-you-go or Pro (including an active 14-day trial), enterprise or administrator access and resource permissions are checked on every call. Active trials include API access until the trial ends. No client secret is required for the public CLI client or supported dynamically registered public MCP clients.

Create personal API keys through Clerk in Quantura Profile. These keys use the `ak_` prefix and are sent as bearer credentials. Existing legacy `qnt_live_` keys remain supported:

```http
Authorization: Bearer ak_REPLACE_ME
```

Never place API keys in query strings, browser storage, client-side bundles, screenshots, analytics events, or logs.

## Get your API key

1. Sign in to Quantura.
2. Open **Profile → Account settings → API keys**. This tab requires pay-as-you-go or Pro (including an active 14-day trial), enterprise or verified administrator access; free accounts without an active trial are excluded.
3. Choose **Add new key**, give it a descriptive name, and set an expiration.
4. If your integration uses an operator-provisioned scoped key, request only the scopes it needs. A personal Clerk key without explicit scopes uses your full personal API scope set, subject to resource ownership and current subscription or trial access.
5. Copy the secret from Clerk and keep it private.
6. Store the key in a server-side secret manager or environment variable such as `QUANTURA_API_KEY`.

The authenticated developer page is available at `/developers/api`. The endpoint reference at `/api/openapi.json` uses the same paid/admin access policy and supplies the Mintlify reference.

## CSV download quickstart

```bash
export QUANTURA_API_KEY="ak_REPLACE_ME"

curl -H "Authorization: Bearer $QUANTURA_API_KEY" \
  "https://quantura.studio/api/v1/workspaces"
```

See [Q Search](/docs/q-search) and [Q Download](/docs/q-download) for public market discovery and history.

## Key lifecycle

Clerk manages personal key names, expiration and revocation. Quantura verifies each key with Clerk on every request, resolves the migrated user ID and checks the current entitlement. Organization keys are not supported by this personal-key flow.

For rotation, create a replacement key, update your integration and revoke the old key. Revocation takes effect for future requests. Legacy Quantura keys store a keyed digest and non-secret prefix; their replacement operation revokes the replaced credential.

## Scopes

Use the narrowest scopes required by the integration. Relevant read scopes are:

- `datasets:read` to inspect or download permitted uploaded CSVs and dataset metadata.
- `workspaces:read` to list current workspace access.
- `forecasts:read` to read authorized Quantura Forecast / Q Forecast jobs and results.
- `predictions:read` to read authorized prediction-analysis resources.

Write/compute scopes such as `forecasts:write`, `datasets:write`, or SageMaker execution scopes are **not required** for a CSV retrieval client.

Scopes do not replace workspace authorization. Quantura also evaluates current membership, role, resource ownership, and plan entitlement on every request. A viewer collaborator may read resources that are currently shared with them, but the same key does not gain permission to modify the owner's workspace.

## Recommended secret handling

```python
import os

api_key = os.environ["QUANTURA_API_KEY"]
headers = {"Authorization": f"Bearer {api_key}"}
```

Do not commit a real key to Git, paste it into Codex prompts, or place it in public examples. Use a placeholder such as `qnt_live_REPLACE_ME` in documentation and tests.

## Clerk account API keys

Sign in and open Profile → Account settings → API keys. This tab is available to
pay-as-you-go or Pro (including an active 14-day trial) and enterprise accounts and verified Quantura administrators. Free accounts without an active trial cannot use API keys. Paid cancellation periods retain access
until the entitlement ends. Clerk owns key creation, expiration and revocation.
Personal `ak_` keys authenticate with `Authorization: Bearer <key>`; the
backend resolves the original migrated UID and checks current paid access and
workspace permissions. Organization keys are not supported by this personal-key
flow. Legacy `qnt_live_` keys remain supported with the same paid-access check.
Keys cannot grant administrator status through editable claims or metadata.
