# Uploaded CSV API

The Uploaded CSV API lists, stores, organizes, and downloads CSV files inside authorized Quantura workspaces. Read and write actions are separately protected by API scopes, current workspace membership, explicit workspace permissions, and resource-specific scope.

Use a scoped `qnt_live_...` bearer key with `datasets:read` for retrieval and `datasets:write` for upload/organization. Add `workspaces:read` or `workspaces:write` when using workspace and collaborator endpoints.

```http
Authorization: Bearer qnt_live_...
```

## List uploaded CSVs

```bash
curl -H "Authorization: Bearer $QUANTURA_API_KEY" \
  "https://quantura.studio/api/v1/uploads/csv?limit=50"
```

The list endpoint returns a stable upload ID, safe filename information, size and integrity metadata when available, CSV dimensions, date/time coverage when unambiguous, inferred granularity, quantile columns, and a server-authorized download endpoint.

Supported list filters should include `workspace_id`, `ticker`, `source`, `from`, `to`, `sort`, `limit`, and `cursor`. Clients should treat unknown metadata as `null`, not as an error.

## CSV metadata

```bash
CSV_ID="qcsv_example"

curl -H "Authorization: Bearer $QUANTURA_API_KEY" \
  "https://quantura.studio/api/v1/uploads/csv/$CSV_ID"
```

A metadata object can include:


## Metadata accuracy rules

Quantura does not fabricate file metadata:

- Ticker, asset class, source, model, and forecast type are returned only when upload/job provenance or a high-confidence parser establishes them.
- A file containing quantile columns is not automatically labeled an ensemble forecast.
- Row and cell counts come from parsed CSV records rather than newline estimates.
- SHA-256 refers to the actual stored file bytes when present.
- A date/time range is returned only when the date column can be parsed without inventing missing information.
- If a timestamp has no year or is otherwise ambiguous, absolute timestamps remain `null` and `metadata_warnings` explains why.
- Internal object paths, credentials, prompts, and private storage details are never returned.

## Download one CSV

```bash
curl -fL \
  -H "Authorization: Bearer $QUANTURA_API_KEY" \
  -o "quantura-$CSV_ID.csv" \
  "https://quantura.studio/api/v1/uploads/csv/$CSV_ID/download"
```

The server re-checks the token, scope, current workspace membership, and resource ownership before serving or redirecting to the file. A download URL must not grant access after authorization is lost.

## Download all accessible CSVs

```bash
curl -fL \
  -H "Authorization: Bearer $QUANTURA_API_KEY" \
  -o quantura-csv-exports.zip \
  "https://quantura.studio/api/v1/uploads/csv/download-all"
```

Bulk export applies the same authorization rules as single-file download. A ZIP must contain only the CSVs the caller is authorized to read. Filters from the list endpoint may be supported for scoped exports.

The ZIP also includes `manifest.json`, `manifest.csv`, and `manifest_summary.json` so automated consumers can verify identifiers, file names, sizes, checksums, and record count before ingestion.

## Upload

The API accepts bounded UTF-8 CSV text or base64 bytes. Do not send both representations.

```bash
python - <<'PY'
import base64, json, os, pathlib, requests

path = pathlib.Path("forecast.csv")
payload = {
    "workspace_id": os.environ["QUANTURA_WORKSPACE_ID"],
    "filename": path.name,
    "content_base64": base64.b64encode(path.read_bytes()).decode("ascii"),
}
response = requests.post(
    "https://quantura.studio/api/v1/uploads/csv",
    headers={"Authorization": f"Bearer {os.environ['QUANTURA_API_KEY']}"},
    json=payload,
    timeout=60,
)
response.raise_for_status()
print(response.json()["data"]["id"])
PY
```

## Rename, move, and copy

```bash
curl -X PATCH -H "Authorization: Bearer $QUANTURA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"display_filename":"AAPL Forecast.csv"}' \
  "https://quantura.studio/api/v1/uploads/csv/$CSV_ID"

curl -X POST -H "Authorization: Bearer $QUANTURA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"destination_workspace_id":"ws_destination"}' \
  "https://quantura.studio/api/v1/uploads/csv/$CSV_ID/move"

curl -X POST -H "Authorization: Bearer $QUANTURA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"destination_workspace_id":"ws_destination"}' \
  "https://quantura.studio/api/v1/uploads/csv/$CSV_ID/copy"
```

Move requires permission to modify the source and upload to the destination. Copy preserves the source and creates a new destination resource with provenance. Bulk variants accept up to 100 unique IDs at `/uploads/csv/bulk-move` and `/uploads/csv/bulk-copy` and return explicit per-file results.

## Shared workspaces

API keys identify a user; they do not freeze a collaborator role. Quantura evaluates the user's current access on every request.

A viewer collaborator with the required read scope may list metadata and download CSVs from a workspace that is currently shared with them. Viewer access is read-only. Removing the collaborator removes future access for the same API key.

To discover available workspace IDs:

```bash
curl -H "Authorization: Bearer $QUANTURA_API_KEY" \
  https://quantura.studio/api/v1/workspaces
```

Then pass `workspace_id` to the CSV list endpoint, or use the explicit workspace route when available:

```text
/api/v1/workspaces/{workspaceId}/uploads/csv
```

## Pagination

List clients should follow the opaque `next_cursor` returned in response metadata. Do not decode or construct cursors in client code.

```python
import os
import requests

base = "https://quantura.studio/api/v1/uploads/csv"
headers = {"Authorization": f"Bearer {os.environ['QUANTURA_API_KEY']}"}
params = {"limit": 100}

while True:
    response = requests.get(base, headers=headers, params=params, timeout=30)
    response.raise_for_status()
    payload = response.json()
    for csv_file in payload["data"]:
        print(csv_file["id"], csv_file["original_filename"])
    cursor = payload.get("meta", {}).get("next_cursor")
    if not cursor:
        break
    params["cursor"] = cursor
```

## Common errors

- `401` — key missing, invalid, expired, or revoked.
- `403` — key lacks `datasets:read`, workspace access is missing, or the current plan/role does not permit the request.
- `404` — CSV upload does not exist or is intentionally hidden from the caller.
- `429` — API rate limit exceeded.

Use the request ID returned by the API when investigating an error. Never include the plaintext API secret in a support request.
