Forecast

Generate quantile bands for the ticker in your chart and save the run so you can re-plot it later.

Daily = trading days. Hourly = hours.
Quantura Horizon always uses fixed bands: P01-P99, P10-P90, P25-P75, plus the P50 median path.
Learn more

Forecasts are stored to your workspace as fixed probability bands. Quantura Horizon saves a P01-P99 outer range, a P10-P90 range, a P25-P75 range, and the P50 median path so every saved run renders consistently.

Forecast length controls how many future timestamps are generated for the selected timeframe. Daily forecasts use trading days (business days). Hourly forecasts are capped to keep the terminal responsive.

Quantura Horizon is optimized for transparent trend and seasonality interpretation with stable uncertainty bands. Quantura stores each run so you can compare results, review confidence structure, and export files for downstream analysis.

Research guide

Use the AWS Forecast metrics documentation to understand how Average wQL, wQL, WAPE, RMSE, MAPE, and MASE are interpreted. Lower error values indicate a stronger forecasting model.

In Forecast Foundry, the point-forecast anchor is the middle quantile column, which is usually the median P50 or 0.5.

For stock prediction analysis, Quantura takes the first actionable business-day P50 in the forecast window and the last valid business-day P50 in the forecast output, rounds both to the nearest 10, and compares those tens-place levels. If the last rounded P50 is below the first, Quantura marks the setup as BUY and communicates an end-date bias toward the upper bound, typically P90. Otherwise it marks the setup as SELL and communicates an end-date bias toward the lower bound.

Screener overview

Quantura Screener dispatches the repository GitHub workflow, waits for the uploaded artifact, and saves the completed run back into your workspace.

Use the market-cap floor to control the universe, then reopen completed runs from My Requests or review the public history feed when scheduled jobs finish.

Workflow

Dispatch launches the GitHub Actions screener with the selected market-cap floor.
Tracking keeps the live workflow status attached to the saved run while the artifact is processing.
Artifacts expose downloadable CSV output as soon as GitHub uploads the screener results.
Workspace stores each run in My Requests so it can be reopened without rerunning the workflow.
Explore auto-publishes completed screener runs so the public feed stays in sync with successful jobs.

Technical analysis intro

Start with trend context (price regime + moving averages), then add momentum (RSI, MACD), and finally confirm participation (relative/current volume, short float).

Treat technical signals as probabilistic confirmation layers. Pair them with earnings timing, analyst targets, and sector context before sizing risk.

Research workflow

1) Run Screener to generate candidates. 2) Validate with Indicators and News. 3) Build quantile ranges in Forecast. 4) Save and compare runs week-over-week.
