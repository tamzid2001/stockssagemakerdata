# Quantura v2.1.0 — Multi-interval forecasts and reproducible research

This release brings together the changes since v2.0.0 with a consistent forecasting workflow across the website, worker, HTTP API and documentation.

## Forecast intervals and API

- Add 5-minute, 15-minute, 30-minute, 4-hour, weekly and monthly forecasts alongside minute, hourly and daily intervals.
- Share aliases, completed-bar aggregation and canonical frequencies across stock, Dukascopy, prediction-market and perpetual history.
- Use Monday UTC weeks and real calendar months, including leap years. Preserve cross-year weekly pages in Dukascopy downloads.
- Count exact-end horizons by future period boundaries; retain interval and quote basis in saved/refresh workflows. Restore saved horizons as bar counts.
- Publish interval capabilities at `GET /api/v1/forecast/models`, update the live OpenAPI schemas and add the read-only MCP capability allowlist entry.
- Add API guides for quantile strategies, causal inference timing, public backtest rules, averaged-basket research, costs, drawdown and validation.

## Data, models and Screener

- Integrate Dukascopy's full published instrument catalog with bid/ask selection, verified decimals, catalog provenance and efficient native candle archives.
- Improve Yahoo request caching, coalescing and cooldown; retain effective-provider metadata during verified Alpaca fallback.
- Improve real-model reliability, context limits, per-quantile weighting and supported tail handling; retain licensing/access gates.
- Unify today's game forecasts with stock/perpetual Screener results. Add provider/outcome filters, actual market links and correct selected-quantile comparisons.
- Use verified kickoff times, genuine four/five-model pregame ensembles and P01/P25/P50/P75/P90/P99 outputs. Update hourly before the game's start hour with a horizon through kickoff plus four hours.
- Improve game historical overlays, forecast navigation, account saving and restoration of the general Forecast form after viewing a game.
- Pace Kalshi discovery, respect rate-limit retry instructions and produce a valid artifact even when discovery is partial or no forecasts qualify.

## Research and reliability

- Add SPY, mega-cap and rolling constituent research with frozen observations and reproducible replay configuration.
- Add separate long/short FTMO-style annual matrices with instrument-specific spacing, costs, swaps, margin assumptions, open liabilities and path-sensitive drawdown.
- Add causal triggered second forecasts for eight FX/index assets using real minute breaches and completed H1 context through the remaining 17:00 UTC session.
- Keep Kalshi coin trading workflows paper only.
- Fix the ensemble worker's missing PyYAML mock-test dependency and CI workflow coverage.
- Improve private artifact retention, repository/storage hygiene and operational observability.

## Product and documentation

- Refresh homepage messaging, mega-cap previews and featured research articles.
- Use relevant distinct blog images, a product-tour video with licensed music and a clear ending poster, and branded PWA presentation.
- Improve theme contrast, footer consistency and mobile navigation. Add device-scoped Support conversation history and its accuracy notice.
- Support consented server-side GA4 event measurement with private credentials.
- Replace the README and publish a current wiki covering setup, forecasting, data, games, strategy research and operations.

## Compatibility and limits

The API stays at `/api/v1`; these are additive forecast intervals and metadata. Existing daily US-stock horizons retain NYSE session semantics. Other market intervals use UTC frequency periods, which can produce prediction timestamps during market closures. Missing bars are not synthesized. Provider retention, entitlements, history length and model requirements still apply.

The public backtest builder remains a bounded long-only, single-position quantile-rule replay. Dedicated research workers implement the separate averaging/short/swaps workflows. Closed-basket win rates are not challenge-pass claims; include floating losses and costs when interpreting research.

MCP API-tool availability depends on the documentation host's plan and refreshed deployment. No live trading or expensive forecast mutation is added as an MCP tool. Provider data and checkpoints retain their separate license conditions.
